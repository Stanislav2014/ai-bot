## Goal

Закрыть две утечки PII в Sentry, обнаруженные при manual CR-9 проверке O-02:

1. **`system_prompt` утекает через breadcrumb message** — structlog `JSONRenderer` рендерит весь dict в `bc["message"]` как JSON-строку, а мой `_before_send` в O-02 чистил только `bc["data"]`. Реальный structlog flow не покрывался.

## Design notes

**Почему JSON parse, а не regex strip:**
- Regex для `"system_prompt": "..."` хрупкий: ломается на escape-sequences, multiline, unicode
- JSON parse — каноничный метод; если `bc["message"]` валидный JSON dict → можно безопасно манипулировать ключами
- Если не JSON (httpx breadcrumb message пустой / Application started / etc.) — пропускаем без вреда

**Почему `before_breadcrumb` отдельный от `before_send`:**
- `before_breadcrumb` вызывается **до** добавления breadcrumb в scope → токен не попадает даже в memory структуру SDK
- `before_send` запускается перед отправкой event'а → к этому моменту breadcrumbs уже накоплены, но он может их править
- Используем оба для defense in depth: `before_breadcrumb` чистит на входе, `before_send` чистит сами event fields (`request.url`)

**Регулярка для токена:**
```
/bot[A-Za-z0-9_:-]+(?=/)
```
Ищет `/bot` + token chars (alpha/digit/`_`/`:`/`-`), предвидение `/` (path delimiter). Замена на `/bot[REDACTED]`. Покрывает Telegram bot API формат `<bot_id>:<auth_token>`.
